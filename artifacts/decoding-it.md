# Decoding it

**Subtitle:** Why building fast doesn't answer the hardest question about software
**Date:** 2026-04-28
**URL:** https://artifactstech.substack.com/p/decoding-it
**Status:** Published — captured from live article on 2026-10-24
**Archive format:** Original article text; Markdown formatting conversion. Images retain source URLs; media embeds are linked, not transcribed.

---

<a href="https://www.getmatter.com/">Matter</a>, the app I used to read articles and save the highlights, introduced a subscription, which I didn’t want to pay for. So, in slightly more than an hour <strong>I (vibe)coded with AI something quick and dirty that does the exact same things.</strong>

\[Vibe-coding becoming a thing was <a href="https://artifactstech.substack.com/p/send-good-vibes">the subject of an Artifacts</a> more than 1 year old, btw\]

This Read Later app (it doesn’t even have a name) may seem to be quite cool, <strong>but I’d argue that it is not.</strong>

<a href="https://substackcdn.com/image/fetch/$s_!6kND!,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Ff2d270be-5267-4dbc-b376-41928cdf1c25_800x450.gif"><img src="https://substackcdn.com/image/fetch/$s_!6kND!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Ff2d270be-5267-4dbc-b376-41928cdf1c25_800x450.gif" alt=""></a>

As you see, it does a few things just right for me:

- <strong>it stores articles</strong> from any website (with an ugly browser extension)

- <strong>it saves them</strong>, so I can read, highlight what matters, add labels in an uglier UI

- and finally <strong>it sends them to the Notion database</strong> I use to write Artifacts.

And yes, although I could go and brag like LinkedIn folks saying ‘I recreated \[insert name of random app\]’ or ‘You can now build anything’, <strong>I tend to think that such narrative is, as most narratives, just a nice story to tell.</strong>

And that this app doesn't make the cut cause <strong>it was built with just my specific needs in mind.</strong>

It is, indeed, true that <strong>non-technical people can nowadays quickly bootstrap functioning apps</strong>, but these are <strong>quite far from well-crafted products</strong> or saying that software organisations are doomed.

True: we may have solved large parts of the complexity of coding, but <strong>it’s not because anyone can write that then anyone can suddenly be David Foster Wallace</strong> or Carrere or whoever you like.

This Artifacts is to decode this story around programming code.

We do live in extraordinary times, for sure:

- <strong>5% of the programming code in GitHub is now written by Claude Code</strong>, the most popular AI for coding. The Head of Claude Code claimed that <a href="https://www.youtube.com/watch?v=We7BZVKbCVw">‘code is largely solved’.</a>

- For the first time in 15 years, <strong>student enrollment in computer science degrees is falling in the US</strong>, according to the <a href="https://www.washingtonpost.com/technology/2026/04/13/computer-science-major-ai/">Washington Post.</a>

- <strong>Some tech companies are firing employees</strong>, including engineers, because of AI - last being Meta which announced it will fire 10% of its staff.

<a href="https://substackcdn.com/image/fetch/$s_!DhXa!,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fea0be385-6f69-4295-a704-b1155f9e8745_1142x754.png"><img src="https://substackcdn.com/image/fetch/$s_!DhXa!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fea0be385-6f69-4295-a704-b1155f9e8745_1142x754.png" alt=""></a>

Yet, <strong>not everything seems to back this narrative.</strong>

The most surprising data is that <strong>demand for software engineers is not dropping</strong>, <a href="https://www.lennysnewsletter.com/p/state-of-the-product-job-market-in-ee9">according to Lenny’s newsletter.</a> So, despite students being reluctant to enrolling in computer science degrees, the job market isn’t showing a steady downfall, for now. <strong>(Maybe the first time in history students are concerned about a sector that is not really shrinking?)</strong>

<a href="https://substackcdn.com/image/fetch/$s_!vrZH!,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fe6a8f258-05e6-4bbf-96f0-57d21575c08b_1456x1259.png"><img src="https://substackcdn.com/image/fetch/$s_!vrZH!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fe6a8f258-05e6-4bbf-96f0-57d21575c08b_1456x1259.png" alt=""></a>

Aside from the job market, which is not the focus of Artifacts, these months and years are incredibly fascinating to speculate about what’s happening to software.

<strong>It is true that coding is becoming a commodity.</strong> Concretely, if you talk to any engineer, writing code by hand is undergoing something similar to what is happening to writing emails for any knowledge worker.

<strong>It’s what I called <a href="https://artifactstech.substack.com/p/writing-is-thinking">meta-writing:</a></strong> we more and more dictate to a machine <em>what</em> we need to write and maybe even <em>how</em> and in what style, <strong>and then we delegate the act of writing or typing <s>words</s> code to machines.</strong>

Yet, this can be framed within the <strong>progressive simplification of creating software</strong> over decades. Without diving into the history of coding, also the rise of API (Application Programming Interfaces) made it much easier to create apps.<br>

<em>skip this paragraph if you know what an API is</em> - APIs is what makes it possible, for instance, for any website to just connect to Stripe, the most popular payment service in the world, and having a working payment process, without building it from scratch. <strong>APIs are, fundamentally, prebuilt</strong> <em><strong>bridges</strong></em> <strong>between applications</strong> -

If before you still needed to handle and oversee the construction of the bridges of API (and many other items of working software), <strong>it is now true that, with AI, all of this is more and more being commodified and automated.</strong>

Or, to put it simpler, <strong>the code can be written by machines themselves</strong>. On this, on the very question if we should even be surprised that machines are good at using themselves, <strong>I’ll probably write an Artifacts.</strong>

Getting something working is fine and great and it is what we all eventually care about with technology = <strong>problems solved, maybe ignoring how.</strong> You want to call your mom with your iPhone, you can’t care less about how it works.

But it doesn’t mean we’ll no longer need people who understand and think through software.

Because getting something working very quick <strong>but overlooking</strong> <em><strong>how</strong></em> <strong>it works</strong> <em><strong></strong></em> <strong>is not great</strong> if you’re to (1) fix something that may break when you will add a new feature, (2) be confident about the security of what you’re creating, and (3) make it fit for the wider public and not just you.

This is also cause there’s a big difference between building something that works for us at first glance and something widely usable, which is what professionals do.

And there’s something even more fundamental than all of this: code was never only the point - <strong>tackling the right problem has always been the harder part.</strong>

------------------------------------------------------------------------

<strong>I don’t want to sound like a doomsayer or a skeptic here,</strong> it’s just a humble exercise to cool down a lot of hype that I often find unjustified.

It is, again, great that anyone (especially non technical people) can sketch prototypes of something: <strong>it cuts time, makes ideas spread, and makes them easier to prove right or wrong.</strong>

Yet, in all the hype around AI coding, there’s one apparent risk that doesn’t pertain to the code: <strong>skipping the question of</strong> <em><strong>why</strong></em> <strong>you’re building that app in the first place.</strong>

Why do you think the app you rushed to organise a trip with friends on a Saturday morning would work for others? <strong>Just because it works? Mmm…</strong>

The fact that it is now so fast and easy to get something working together with automated code writing may let us overlook:

- <strong>why we’re investing time</strong> in building something

- whether what we’re doing <strong>is the best way</strong> to get to a result

- and <strong>whether it will hold up</strong> beyond the first version

Just as writing is thinking and taking the time to write is valuable, <strong>we should handle with care the velocity and the ease at which AI enables us to build something.</strong>

Are velocity and ease just an unparalleled advantage or <strong>do they let us overlook why we do something?</strong>

If you have ever worked in a software company, you know that before handing off to engineers, <strong>there’s first a whole preliminary phase:</strong> defining what needs to be built, what problem it should tackle, what a bad solution would look like, how to make it technically possible. <strong>All before a line of code is written.</strong>

If AI makes it faster and easier to skip that phase and get something working, <strong>I’m not sure we will go that far.</strong>

<strong>The value of software primarily lies in the problems it tackles, not in having functioning code.</strong> If your shiny product works but doesn’t tackle a real problem, it’s trash.

And it is only good that with AI it is easier and quicker to develop such trash if one has the honesty to go back to the drawing board and rethink the problem.

Asking such questions and making sure that what we intend to build is the first step. <strong>Only after, making it real, now more easily and faster with AI, is the second one.</strong>

And this connects back to the students concerned about their jobs despite a job market that hasn’t collapsed. <strong>It is true that writing code is becoming easier - but this commodification is the opportunity to focus on the problems we want to tackle.</strong> A largely abused (and not perfect) metaphor is that of calculus machines: it’s great to be faster at doing math if we know what math we need done.

One may also argue that this is even better: we’re cutting the time spent on the part that can be automated <strong>to focus on the questions.</strong>

Then, once the questions are tackled, <strong>making sure that the code</strong> (likely mostly written by machines) <strong>is understandable, curated, and sustainable over time</strong> - that is still critical, and likely to become the work of current and future engineers.

One thing is just writing. <strong>A completely different one is knowing what to write and then writing it well.</strong>
